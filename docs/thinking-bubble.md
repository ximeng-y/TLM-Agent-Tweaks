# 思考链气泡显示

在 TLM 原有「少女思考中」等待气泡内，滚动显示模型本轮的思考（reasoning）增量。
纯展示层：不改变请求、不改变工具执行、不写入聊天历史。

## 显示流程

同一轮对话内气泡在三种形态间切换，均由服务端状态驱动：

| 阶段 | 气泡内容 |
| --- | --- |
| 模型思考中 | 模型最近一行思考文本（单行） |
| 工具执行中 | 该阶段不显示思考，气泡回落到 TLM 原生的「原生模式」提示文本 |
| 请求结束 / 失败 / 取消 | 清空思考内容，气泡恢复原生形态 |

- 思考文本以**单行**滚动：保留最后一个换行符之后的内容，新行出现即视为换行、从头
  重新填充；单行长度上限 2048 个码点，超出时从行首截断（保留代理对边界，不会截出
  半个 emoji）。
- 等待气泡宽度固定为 96（标题更宽时取标题宽度）：整行未超宽时从**窗口左侧**开始
  填充，新字逐个向右延伸；超宽后只保留可见后缀并**右侧对齐**，使最新内容贴右。
- 右上角标题、左侧旋转图标、背景纹理与气泡的左右/居中位置均沿用 TLM 原生
  `WaitingChatBubbleRenderer` 的布局，仅替换正文渲染。

## 与流式回退的关系

- 只有**思考增量**（`REASONING_DELTA`）参与显示；答案增量（`TEXT_DELTA`）不显示。
- 流式失败改用普通模式重发时**不补播**中断前的思考片段：气泡立即清空并切到原生
  工具提示文本，避免把中断的流式片段当作有效输出（与
  [docs/llm-streaming.md](llm-streaming.md) 的「回退不是续传」一致）。
- 重试等待、站点排队期间进入原生模式阶段，不继续滚动旧思考。

## 玩家开关

- 位置：AI 聊天窗口 → Agent Tweaks 设置页 → 顶部「显示思考链：开启 / 关闭」按钮。
- 作用域：**本机玩家**，只影响自己看到的气泡；不改变服务端请求，也不影响其他玩家。
- 配置文件：`config/tlm_agent_tweaks-client.toml`，键 `thinking.showReasoning`，默认
  `true`。游戏内按钮与该文件是同一份客户端本地配置，**不加入 COMMON，不同步到服务器**。
- 关闭时气泡直接使用 TLM 原生 renderer，思考文本仍会在服务端生成（只读展示不影响
  请求），只是不发给该玩家。

## 传输

服务端每个「展示会话」（一轮请求）按需发送快照，而非让客户端累加增量：

- 快照包含阶段（思考 / 原生 / 清空）、当前单行文本、单调递增的修订号与气泡 ID。
- 每 tick 至多对每个发生变化的会话发一次，内容未变化不重发。
- **一个气泡同时只由一个会话负责**：服务端在发布前认领气泡归属，已被其它存活会话
  占用的回调让位。**气泡归属跟随 callback 跨请求保留**，不按请求创建顺序推断父子关系；
  父请求在**工具真正执行之前**（此时 TLM 已刷新出新气泡
  ID、子请求尚未创建）同步完成认领，而不是等到每 tick 批量发送时再按顺序决定。
  工具续接会为新一轮请求新建会话并让旧会话退休（先发清空再发新状态），但不释放归属；
  即使工具等待超时后子请求仍在运行，也不能抢占父请求下一轮的气泡。归属在整轮终态或
  气泡切换时释放。
  知识型工具（`GroundedAnswerCallback`）复用父气泡的子请求则遵守父阶段而不另起显示。
- 客户端按（维度, 女仆 UUID, 展示会话 ID）缓存，只在快照对应的气泡 ID 正是当前
  等待气泡时才参与渲染，因此气泡对象被 TLM 重建（新气泡 ID）时会自动失效；同一气泡
  上若短暂存在多个会话，按展示会话 ID 最大者胜出，不依赖 Map 遍历顺序。
- 玩家开始跟踪女仆时补发当前有效快照，因此中途靠近也能立即看到正在滚动的思考。
- 网络包以 `optional` 方式注册，未安装本 mod 的客户端不受影响；发送前逐玩家检查
  通道是否协商成功。

## 已知边界

- 服务端每 tick 仅在下发时校验等待气泡是否仍存在；若气泡在两次校验之间被 TLM 销毁，
  最多残留一个 tick 的旧文本。
- 客户端对绑定已失效（气泡消失、女仆不在客户端世界、不在当前维度）的条目按 40 tick
  超时淘汰，覆盖「玩家离开跟踪范围后收不到服务端清空」的情况。
- 未在真实客户端实机验证滚动观感与超长文本截断效果，相关验收项待实机确认。
